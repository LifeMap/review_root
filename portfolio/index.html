01 / Overview

프로젝트 개요

패션 쇼핑 시 소비자가 겪는 핵심 불편 3가지를 기술로 해결합니다.

🔍

문제 1: 리뷰 분산

동일 상품이 여러 플랫폼에 존재하지만 리뷰를 따로 확인해야 해 시간이 낭비됩니다.

🤖

문제 2: 광고성 리뷰

협찬·광고 리뷰가 섞여 있어 진짜 후기를 찾기 어렵고 잘못된 구매 결정으로 이어집니다.

👤

문제 3: 비개인화

수백 개 리뷰 중 내 체형·사이즈에 맞는 리뷰를 찾는 것은 사실상 불가능합니다.

솔루션

1

멀티 플랫폼 리뷰 통합

29cm, 무신사, W컨셉, 커들리버니 등 4개 플랫폼을 Playwright로 자동 수집. 매일 새벽 2시 자동 실행.

Playwright BullMQ
2

AI 기반 광고 필터링

GPT-4o-mini로 광고성 판별 (isSponsored + confidence 0.7 임계값). Few-Shot 학습으로 오탐률 30% → 5% 감소.

OpenAI Batch Processing
3

체형 기반 개인화

키·몸무게 유사도 공식으로 비슷한 체형의 리뷰어 후기를 우선 노출. 사이즈 피드백(small/perfect/large) 통계 제공.

Elasticsearch MySQL

05 / Code Highlights

핵심 코드 하이라이트

빌드 타임 에러 방지를 위한 lazy 초기화 패턴 및 핵심 설계 결정

DB Lazy Proxy 패턴

Next.js 빌드 타임에 DB 연결을 시도하면 에러가 발생합니다. Proxy 객체로 감싸 실제 접근 시점까지 초기화를 지연합니다.

src/services/db/index.ts
// 실제 DB 인스턴스 — 최초 접근 시 lazy 초기화 let _pool: ReturnType<typeof mysql.createPool> | null = null; function getPool() { if (!_pool) { _pool = mysql.createPool({ uri: process.env.DATABASE_URL!, connectionLimit: 10, }); } return _pool; } // Proxy 객체로 export — 빌드 타임 안전 export const db = new Proxy({} as ReturnType<typeof drizzle>, { get(_, prop) { return (getDb() as Record<string | symbol, unknown>)[prop]; }, });

OpenAI Lazy Singleton 패턴

serverExternalPackages에 등록된 openai 패키지도 동일 원리로 lazy 초기화. 환경변수가 없을 때 빌드 실패를 방지합니다.

src/features/ai-processing/analyzer.ts
// openai 인스턴스 — 최초 API 호출 시점에만 생성 let _openai: OpenAI | null = null; function getOpenAI(): OpenAI { if (!_openai) { _openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY }); } return _openai; } // next.config.ts — 빌드에서 번들 제외 // serverExternalPackages: ["openai","bullmq","ioredis"]

AI 분석 — Exponential Backoff 재시도

OpenAI Rate Limit 및 일시적 장애에 대비한 3회 재시도 로직. 실패 시 기본값을 반환하여 서비스 중단을 방지합니다.

analyzer.ts — retry logic
const MAX_RETRIES = 3; const RETRY_DELAY_MS = 1000; for (let attempt = 1; attempt <= MAX_RETRIES; attempt++) { try { const completion = await getOpenAI().chat.completions.create({ model: 'gpt-4o-mini', temperature: 0.1, // 일관성 우선 response_format: { type: 'json_object' }, }); break; // 성공 시 루프 탈출 } catch (error) { if (attempt < MAX_RETRIES) { const delay = RETRY_DELAY_MS * Math.pow(2, attempt - 1); await sleep(delay); // 1s → 2s → 4s } } } // 실패 시 DEFAULT_RESULT 반환 — 서비스 중단 없음

JWT 미들웨어 — API 보호

Edge Runtime 호환 jose 라이브러리로 JWT 검증. /api/v1/admin/*는 role='admin' 필수. 토큰은 localStorage에만 저장(쿠키 미사용).

src/middleware.ts
export async function middleware(req: NextRequest) { const payload = await verifyTokenFromHeader(req); if (!payload) return error('UNAUTHORIZED', 401); if (payload.role !== 'admin') return error('FORBIDDEN', 403); return NextResponse.next(); } export const config = { matcher: ['/api/v1/admin/:path*'], };

AI 배치 처리 — 15개 단위 병렬

1,000개 리뷰를 1개씩 처리하면 1,000번의 API 호출이 필요합니다. 15개 묶음 처리로 API 호출을 67번으로 줄여 비용을 93% 절감합니다.

ai-processing / batch
const AI_PARALLEL_BATCHES = 15; // env: AI_PARALLEL_BATCHES for (let i = 0; i < reviews.length; i += AI_PARALLEL_BATCHES) { const batch = reviews.slice(i, i + AI_PARALLEL_BATCHES); const results = await analyzeReviews(batch); await saveAnalysis(results); } // 10자 미만 리뷰는 AI 스킵 (추가 비용 절감) const validReviews = reviews.filter(r => r.content.length >= 10 );

크롤러 레지스트리 패턴

플랫폼별 크롤러를 레지스트리에 등록해 동적 선택. 새 플랫폼 추가 시 registry.ts 한 파일만 수정하면 됩니다.

src/features/crawlers/registry.ts
const CRAWLERS: Record<string, PlatformCrawler> = { '29cm': twentynineCmCrawler, 'musinsa': musinsaCrawler, 'wconcept': wconceptCrawler, 'cuddlybunny': cuddlybunnyCrawler, // 새 플랫폼 추가 시 여기에만 추가 }; export function getCrawler(platform: string) { return CRAWLERS[platform] ?? null; }

BullMQ 실패 잡 재시도 — 큐 API 패턴

어드민 대시보드에서 실패 잡을 개별 또는 전체 재시도할 수 있습니다. 큐 이름을 동적 라우트로 받아 모든 큐에 공통 적용되는 단일 API 패턴입니다. /api/v1/admin/queues/[queueName]/retry

api/v1/admin/queues/[queueName]/retry/route.ts
// 개별 또는 전체 실패 잡 재시도 export async function POST(req, { params }) { const { queueName } = await params; const { jobIds } = await req.json(); // 없으면 전체 재시도 const queue = new Queue(queueName, { connection }); const failedJobs = jobIds ? await Job.fromIds(queue, jobIds) : await queue.getFailed(0, 999); await Promise.all( failedJobs.map(j => j.retry()) ); return ok({ message: `${failedJobs.length}개 재시도 완료` }); }

광고 판별 수동 오버라이드

AI가 판단한 광고 여부를 관리자가 직접 수정할 수 있습니다. 리뷰 행 클릭 → 인라인 확장 → "광고로 변경" / "광고 아님으로 변경" 버튼. 실시간 UI 업데이트 후 PATCH /sponsored-reviews/:id 호출.

관리자 시스템

role='admin' JWT 인증으로 보호되는 풀스택 운영 도구. 파이프라인 제어, 큐 모니터링, 리뷰 검수, AI 프롬프트 관리를 단일 대시보드에서 처리합니다.

인증 & 접근 제어

JWT 토큰은 localStorage에만 저장합니다(쿠키 미사용). 어드민 레이아웃(admin/layout.tsx)이 클라이언트 마운트 시점에 getCurrentUser()로 토큰을 파싱해 role을 확인합니다. role이 'admin'이 아니면 즉시 /로 리다이렉트합니다. API 라우트는 미들웨어(Edge Runtime)에서 Authorization 헤더를 재검증합니다.

08 / Challenges

기술적 도전과 해결

개발 과정에서 맞닥뜨린 주요 문제와 해결 방법

동적 콘텐츠 크롤링

문제: SPA 구조의 패션 플랫폼은 JavaScript 렌더링 후에만 리뷰 데이터가 나타남. 무한 스크롤, AJAX 페이지네이션, 플랫폼별 상이한 HTML 구조.
해결: Playwright 헤드리스 브라우저로 실제 브라우저 동작 시뮬레이션. Docker 환경 메모리 이슈는 --disable-dev-shm-usage 플래그로 해결. waitForSelector + networkidle 대기로 안정적 데이터 수집.
결과: 4개 플랫폼 안정적 크롤링, 재시도(3회 Exponential Backoff)로 99%+ 성공률

AI 분석 정확도 & 비용

문제: 광고성 리뷰 오탐률 30% (긍정적 리뷰를 광고로 분류). 일일 10,000+ 리뷰를 1개씩 처리하면 API 비용이 기하급수적으로 증가.
해결: Few-Shot Learning — 관리자가 검증한 오탐 사례를 프롬프트에 동적 포함. 배치 처리 (15개 묶음) + 짧은 리뷰(10자 미만) 스킵으로 API 호출 대폭 감소.
결과: 오탐률 30% → 5% 감소 / API 비용 93% 절감 (1,000 → 67 호출)

체형 정보 파싱

문제: 플랫폼마다 체형 정보 형식이 다름. 29cm: ["163cm", "62kg"] 구조화 배열. 무신사: "174cm · 72kg" 텍스트. 커들리버니: "170cm/55kg/44사이즈" 자연어 혼재.
해결: 플랫폼별 정규식 패턴 매칭 우선 적용. 다양한 표현 지원 ("170cm", "170센치", "170" 등). 추출 실패 시 null 저장 후 검색에서 제외하지 않는 Fallback 전략.
결과: 주요 플랫폼 체형 정보 추출률 85%+ 달성

Next.js 빌드 타임 안전성

문제: openai, bullmq, ioredis 등 런타임 전용 패키지가 빌드 시 환경변수 없이 로드되면 빌드 실패 또는 번들 비대화 발생.
해결: next.config.ts의 serverExternalPackages로 번들에서 제외. DB는 Proxy 패턴, OpenAI/JWT는 lazy singleton으로 런타임 접근 시점에만 초기화. API Routes에 export const dynamic = 'force-dynamic' 적용.
결과: 빌드 타임 에러 0건, 런타임 초기화 안정화
